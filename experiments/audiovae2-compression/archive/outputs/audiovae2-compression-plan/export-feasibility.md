# Export feasibility for the narrower stages 2–4 group

Read-only source audit, 2026-09-10. This note identifies reuse and required integration work. No exporter or native kernel was changed, and no compressed ONNX runtime was executed for this audit.

The proposed model can retain the existing native operation families. Changing internal widths does not inherently require a new kernel family. It cannot use the current automatic recipe unchanged, however: that recipe deliberately authenticates the original checkpoint and several exact derived graphs.

| Component | Existing behavior | Implication for the candidate |
| --- | --- | --- |
| Public preparation | [prepare.py](../../work/fast-audiovae/src/fast_audiovae/prepare.py) calls [verify_model](../../work/fast-audiovae/src/fast_audiovae/assets.py), which requires the original ONNX and external-weight SHA256 values | Create an explicit experimental preparation entry with a new authenticated checkpoint/export manifest. Do not disable production checksum checks. |
| ConvTranspose lowering | [upsampling.py](../../work/fast-audiovae/src/fast_audiovae/graph/upsampling.py) derives `Cin` and `Cout` from `[Cin,Cout,2*stride]` weights and checks the precise crop | The new 1024→256, 256→128 and 128→128 projections can use this general lowering if export preserves the expected causal trim. Actual output and phase parity still need validation. |
| Pointwise matrices | [pointwise.py](../../work/fast-audiovae/src/fast_audiovae/graph/pointwise.py) lowers dense kernel-one convolutions using actual weight dimensions | Smaller matrices remain physically smaller. Avoid exporting zeros into the old dimensions or padding channels solely to reuse a recipe. |
| Snake and depthwise | [elementwise.py](../../work/fast-audiovae/src/fast_audiovae/graph/elementwise.py) proves channels and per-channel constants from the graph | Existing operator families can represent the new widths. Retaining all residual units preserves the expected total of 18 depthwise and 43 Snake patterns; changed export syntax may still require matcher work. |
| Three-unit residual fusion | [streaming.py](../../work/fast-audiovae/src/fast_audiovae/graph/streaming.py), lines 516–524, uses a 25-input `StageStackF32` with 78 history frames per channel | Nine units in the replacement preserve the three-unit/dilation structure. New widths and repeated stage channel counts require regenerated shape proofs and explicit stage selection, not blind reuse of old node lists. A later two-unit stack needs a different or generalized fusion/state contract. |
| Specialized stage-4 fusion | [upsample rewrite](../../work/fast-audiovae/experiments/cpu-stage/upsample/rewrite.py) and [projection kernel](../../work/fast-audiovae/experiments/cpu-stage/upsample/projection.c) implement the old 256→128 stride-two path; the projection loops assume 256 input columns | The candidate's stage 4 is 128→128. This specialized kernel cannot be reused by changing a graph attribute. Initially use generic projection plus native phase/residual operations. Adapt the specialized input dimension only if its recovered cost matters. |
| Streaming histories | [streaming graph conversion](../../work/fast-audiovae/src/fast_audiovae/graph/streaming.py) derives most state channels from graph shapes; specialized upsampling has fixed channel checks | Regenerate states for the new graph and authenticate its schema. Preserve zero startup, phase ordering and no additional lookahead; do not transplant old state tensors based only on names. |
| Automatic optimized selection | [x86 recipe](../../work/fast-audiovae/src/fast_audiovae/recipes/x86.py) authenticates original, intermediate, selective-precision, scheduling and streaming artifacts by exact hash | Use a separate experimental model identity and bundle while qualifying. Do not replace old expected hashes or label the new model as an already validated production recipe. |

The shortest safe path is: materialize authenticated trained weights into a new explicit-width decoder export; prove an exact-copy export first; run standard ONNX plus general native FP32 lowerings; regenerate independent streaming states; and check candidate PyTorch/full ONNX/streaming parity. Then restore only the specialized optimizations whose shape contracts remain valid or have been deliberately extended. The first upsampling stage is outside the changed group, so its existing mathematics and dimensions remain available, although names and recipe identity may change.

Selective INT8/packed-matrix generation is a separate approximation step. It needs new actual matrix dimensions, newly generated packing/scales and a fresh quality receipt against this candidate's floating-point output. Existing source-name allowlists and graph hashes are not evidence that the narrower model is already supported. Full-kernel dimensions, packed buffer sizes and selected recipes must be reported before claiming the static 42.45% MAC saving translates into streaming RTF.
