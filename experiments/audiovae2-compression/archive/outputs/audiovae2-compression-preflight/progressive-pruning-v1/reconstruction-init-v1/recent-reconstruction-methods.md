Read-only comparison, 2026-09-11. No code, model, optimizer, data or runtime changes were made.

GRAIL supports the rationale for B, but does not establish a missing cure for our stage2→3 or startup errors. The ESWA paper suggests a more distinct possibility: prepare the retained representation before deleting channels. Its inaccessible full methods limit how precisely that possibility can be assessed.

**GRAIL, CPAL2026.** I read the complete author-posted methods and limitations, and inspected the authors' compensation implementation. Section3 learns a post-activation hidden reconstruction `H ≈ H_P Bᵀ` by ridge regression, then folds `B` into the consumer: `W_new = W B`. The paper explicitly derives an equivalent direct consumer-output ridge problem. Its convolution rule shares a channel reconstruction across spatial taps. It describes sequentially recollecting statistics after upstream pruning. The displayed dense formulation retains the consumer bias and penalizes the full fitted weights; its stated ridge scale is `alpha*mean(diag(G_PP))`, with alpha from1e-4 to5e-3. Reported tests concern vision and language models. The authors identify distribution shift and local compensation as limitations, and joint multi-layer compensation as future work. [Full paper, sections3 and5](https://arxiv.org/html/2602.23795v2), [published record](https://proceedings.mlr.press/v328/tang26a.html).

The inspected `MagnitudeCompensator` implementation solves an uncentered FP32 Gram system, scales ridge by `mean(diagonal)+1e-3`, falls back from `solve` to `lstsq`, and directly assigns the fitted weight. Its final comments say its bias correction was removed. This is one implementation path, not proof that all repository methods have identical bias policies. [Author code](https://github.com/TWWinde/GRAIL_Compensation/blob/main/grail-llm/lib/compensation.py).

Our comparison/inference from the existing B source:

| Question | What B already does or would still require |
|---|---|
| Compensate removed inputs without extra inference layers? | B already folds fits into the four existing native operators. Replacing it with a hidden-map parameterization alone does not introduce a new local representational capability. |
| Account for upstream damage? | B recomputes actual student inputs after each fitted operator; the three residual targets use teacher complete-RU selected outputs minus the current student skip. |
| Preserve temporal upsampling behavior? | B fits all native stride5/kernel10 taps using current/previous frames and five phases with one shared bias. A shared instantaneous channel reconstruction across taps is a more restricted candidate, not an automatic improvement over this native fit. |
| Numerical/regularization difference? | B uses centered FP64 statistics, an unpenalized shared intercept, and delta ridge toward the original sliced operator at fixed1e-6 trace/dimension. Different priors could change generalization, but the publication does not establish which prior is better for this decoder. |
| Solve startup exactly? | No pooled regression objective guarantees every low-energy startup window. Our valid masks, zero-history geometry and held-out per-window checks remain necessary. Neither the hidden-map formulation nor mean correction alone imposes a startup equality constraint. |

**Two-stage reconstruction, ESWA2026.** The accessible primary abstract, introduction and section snippets describe first sparsifying channels scheduled for removal so information concentrates in retained components, then pruning and reconstructing original layer outputs while modeling accumulated errors through a holistic reconstruction objective. The publisher reports512 calibration images for CIFAR and2048 for ImageNet; its ResNet-50 example retains72.58% accuracy at1.73× FLOP reduction. This is classification evidence, not near-lossless audio evidence. I could not retrieve an openly accessible full method or find an author-linked official implementation in the bounded search; the publisher requires organizational access/purchase. Exact first-stage penalties, optimization schedule and global-error equations remain unverified. [Primary article and available section snippets](https://www.sciencedirect.com/science/article/pii/S0957417425025473), [DOI](https://doi.org/10.1016/j.eswa.2025.128930).

Practical implication, stated as inference: B changes consumers after the hard cut; it does not first teach the full-width producer to concentrate useful information in channels that will survive. That pre-cut preparation is the substantive new direction worth understanding if B recovery fails. It would require a separate full-width student branch, the original teacher kept fixed, and subsequent native pruning. Current B recovery already optimizes the complete compressed group and final waveform, so merely adding a broadly described post-pruning global reconstruction stage would overlap the work underway. Neither paper verifies causal audio startup preservation or justifies interrupting the fixed2000-update B comparison.
