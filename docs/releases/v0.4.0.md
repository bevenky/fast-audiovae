# v0.4.0 wheel validation

This release packages the Apple GPU decoder already qualified on main. The `gpu` extra installs PyTorch 2.14.x. CPU installation does not install Torch, and CPU, streaming and one thread remain the defaults.

| Check | Result |
| --- | --- |
| Packaging and GPU API tests | 122 passed |
| Fresh Apple wheel installation without Torch | Passed |
| Default CPU after installing the GPU extra | Passed; Torch was not imported |
| GPU 40/80 ms streaming and independent batch calls | Passed on Apple M5 Max |
| Stream state, reset and output sample counts | Passed |
| Wheel contents, dependency metadata and file hashes | Passed for Apple, Linux and portable wheels |

The installed-wheel smoke check used English and zero latent inputs, with a 120 ms sequence for each. It compared samples with the pinned original ONNX decoder at absolute tolerance 1e-5 and relative tolerance 1e-4. Maximum absolute error was 6.48e-8 on CPU and 7.36e-8 on GPU. GPU state remained on MPS with CPU fallback disabled. These are packaging checks, not new perceptual quality or speed measurements; the broader GPU comparison remains in [Apple GPU validation](../apple-gpu.md).

Native CPU files are byte-identical to the verified v0.3.0 payloads. Linux inference was not rerun for this packaging release. The updated independent CPU batch path is included and was checked through the installed Apple wheel. Experimental native worker APIs are not part of the retained binary contract.

The [validation receipt](v0.4.0-validation.json) records artifact hashes and sample comparison results. Release assets include three wheels, a source archive and `SHA256SUMS`.
