# v0.4.1 wheel validation

This release packages the accepted AMD streaming kernels and exact-output Intel matrix implementation. Apple retains the validated native CPU kernels and optional GPU backend. CPU, streaming and one inference thread remain the defaults.

| Check | Result |
| --- | --- |
| Maintained test suite | 528 passed; 1,963 subtests passed |
| Fresh Apple wheel installation without Torch | Passed; selected the native CPU streaming recipe |
| Apple 40/80 ms packets, reset and independent batch calls | Passed against the original decoder |
| Installed AMD package with the qualified cached bundle | 57 exact waveform/state checks; empty and reset checks passed |
| Intel package and native implementation | 37 Python modules and 44 vendor files match the fully qualified development wheel exactly |
| Apple native payload and GPU modules | Byte-identical to v0.4.0 |
| Wheel inventories, dependency metadata, source archive and hashes | Passed for all three wheels and the source archive |

The Apple smoke check used English and zero latent inputs, with a 120 ms sequence for each. All five waveform comparisons passed at absolute tolerance 1e-5 and relative tolerance 1e-4; maximum absolute error was 6.48e-8. It also verified empty calls, reset and output sample counts. CPU installation did not install or import Torch.

The AMD release check used the installed wheel with ORT 1.29 and the existing qualified decoder bundle. A 40/80/80 ms sequence matched the prior package exactly, including all 18 state arrays after each packet. Four release calls and four reference calls were made; all 11 loaded native files matched the release payload. Fresh automatic graph preparation was not rerun. Shared memory on the test host is mounted noexec, so the installed CPU helper correctly selected the portable fallback there. The exact helper was separately verified and executed on normal executable storage, where it detected AMD/VNNI and selected the expected native recipe. The saved decoder bundle was unchanged.

Intel inference was already qualified through the exact development-wheel implementation with 4,266 state-array comparisons and 40 waveform-sequence comparisons. This release checks package equivalence rather than rerunning that experiment. See [Intel validation](../intel-serving.md). No experimental Intel Snake change is included.

The combined Linux wheel keeps AMD and Intel binaries in separate directories, retains their redistribution notices and verifies the complete dependency inventory. Both use the ORT API29 contract. Linux installations select ORT 1.29; the AMD implementation has separately passed checks on ORT 1.29 and 1.30. See [AMD validation](../amd-serving.md).

The GPU execution path was not rerun for this CPU packaging release. Its three implementation modules and the Apple native payload are byte-identical to v0.4.0; the optional `gpu` extra retains PyTorch 2.14.x. Existing [GPU validation](../apple-gpu.md) still describes that implementation.

These are release checks, not new quality or speed measurements. Apple INT8 research is separate and has not changed the default kernels. The [receipt](v0.4.1-validation.json) records artifact hashes and validation scope.
